# 企业经营分析决策平台

面向企业高层管理的经营分析决策平台。覆盖经营指标看板、财务多维分析、销售漏斗洞察、客户画像构建、供应链效率监控、人力效能评估、经营预测模型、异常预警与决策建议推送的完整企业分析链路。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 窗口预警与决策联动

异常预警中心在原“预警记录维护”之外新增窗口预警链路：

1. **观测接入**（`POST /api/alert/observations`）：观测带事件时间与接收时间，按事件时间归窗。
   同一观测编号 + 相同内容重复提交只生效一次；内容变化按迟到更正处理，旧版本保留。
2. **阈值规则版本**（`GET/POST /api/alert/rules`）：规则含适用范围、生效区间、阈值上限、
   连续超限次数与分级标准。每条观测使用其**事件时刻**生效的版本，跨越阈值调整的窗口
   在 `实际阈值` 中按版本分组列出，不会用新阈值解释旧观测。
3. **窗口聚合**：`GET /api/alert/windows` 返回窗口成员、逐条判定、连续段、待补齐缺口。
   缺报记为缺口且不按恢复处理；断续超限保留证据但不触发。
4. **分级数据集**：`GET /api/alert/dataset` 是跨模块读取的唯一入口，带数据集版本。
   同一窗口命中多条规则时逐条保留 `预警`，窗口级别取最高，但不会丢掉其他超限项。
5. **更正审计**（`GET /api/alert/corrections`）：说明原预警是否被更正及依据；
   不再触发的预警进入 `已更正预警`，保留原阈值与触发依据，不做无痕删除。
6. **计算原子性**：每次计算先在副本上完整构建，再整体替换。计算失败时旧数据集与旧审计
   都保持原样，重试不会出现新旧参半；内容无变化的重算不会提升数据集版本。

决策建议推送新增：

- `POST /api/decision/briefs`：从分级数据集生成建议，把预警影响映射到 `收益输入`、`风险输入`，
  并输出 `处置优先序`。建议固定 `引用数据集版本` 与每条 `引用窗口` 的窗口版本。
- `GET /api/decision/briefs/check`：推送前核对窗口版本、预警级别与更正标记。
- `POST /api/decision/briefs/{编号}/actions`：`核对推送` 会拦下引用已过期的建议；
  `标记已更正引用` 把引用到已更正预警的事实写回建议，需刷新后重新推送。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
